# 功能规格：播放列表侧边栏 —— 分组 / 文件夹

> 状态：**已实现（v1.2.2）**。本文档记录「分组/文件夹」功能的需求、选定方案与决策过程。
> 关联项目约定见 `agents.md`；它是排序功能的子功能，实现集中在 `src/ui.js` 侧边栏，涉及存储层 `src/storage.js`。

---

## 1. 目标

在播放列表侧边栏中新增**分组（文件夹）**能力，把视频按「系列」组织（如游戏A系列、游戏B系列）。分组作为**排序功能的子功能**，在排序模式下创建，但生成后在**普通模式与排序模式都可见**（可重命名、收起/展开），分组关系**持久化**（收起状态每次加载重置为收起）。

## 2. 交互规格（已确认）

### 2.1 成组（排序模式下）
- 多选若干视频 → 点击**「成组」**按钮 → 归为同一组。
- **允许重新成组**：选中的视频（哪怕已在别的组）统一并入新建组；原组若被抽空则**删除该组**。
- 组内成员收拢为**连续块**，放在**最早选中项的位置**（保持相对顺序），并对成员**退一格缩进**，标识为子级而非顶层同级。

### 2.2 文件夹标签
- **命名**：点击名字可**重命名**（inline 输入，Enter／失焦提交）。默认名「分组N」。
- **播放按钮（v1.2.1）**：组头工具区有 ▶ 按钮，点击播放**组内第一个视频**、从断点续播，逻辑与直接点击该视频的播放按钮完全一致。
- **选中指示**：排序模式下组头前显示一个小勾选框：**全部成员被选中**时勾选并高亮（`selected`），**部分成员被选中**时显示圆点（`partial`），折叠时也能看出是否选中该组。
- **收起/展开**：点击折叠箭头切换；**默认收起**（每次加载页面都重置为收起，手动展开不跨刷新保持）。
- **收起显示**：标签显示
  - **成员数量**；
  - **该文件夹第一个视频的信息**：名字、分P、断点（进度/看完标记）。
  展开后显示缩进的组内成员。
- **排序模式下点击组「头」**：**切换选中**该组——未全选则选中该组全部成员，已全选则取消该组；便于再点「自动排序」整组内排。

### 2.3 自动排序与分组
- **组内排序、组间不排**：选中项按所属组分组（含「未分组」）；每组内按 `pubdate` 在**原位置内重排**，**绝不跨组移动**。未分组项同规则处理。
- 点击组「头」切换到全选该组成员后，再点自动排序即对该组做组内排序。

### 2.4 拖拽（全部纳入）
- **拖文件夹标签** → 整体移动该组（作为块）。
- **拖成员到文件夹上** → 加入该组（进组）。
- **拖成员到顶层位置** → 移出该组（变成未分组）。
- 组内成员拖动 → 组内换序（受组边界约束）。

### 2.5 取消分组
- 排序模式下选中组内成员 → 点**「取消分组」** → 拆出成员（变未分组）；组空则删除。

## 3. 数据模型

- 新增存储 key `biliplaylist:groups` = `{ version:1, groups:[{ id, name, collapsed }] }`。
- `list` 各 item 增加可选 `groupId`（`undefined` = 未分组）。
- 组内成员在列表中**连续**占位；每次成组/移动后维护该约束。
- 旧数据无 `groupId` 即未分组，**天然向后兼容**，无需迁移。

## 4. 开发步骤

- **A 数据层**：`groups` 存储封装（get/save、按 id 查、删空组）；`list` item 支持 `groupId`。
- **B 渲染**：`renderList` 按「组边界」遍历——先渲染文件夹标签（选中指示/名字/折叠箭头/成员数/收起时首条摘要），再渲染缩进成员；收起时跳过成员。
- **C 成组**：排序模式选中 →「成组」→ 新建组（自动命名/默认收起）→ 归并选中项（允许跨组重排、抽空原组删除）→ 收拢连续块 → 存 `list`+`groups`。
- **D 标签交互**：重命名（输入时阻止按键冒泡，避免触发 B 站播放器快捷键）、收起/展开（会话内，每次加载重置收起）；排序模式点组头切换选中/取消该组全部成员。
- **E 自动排序**：按所属组分桶 → 每组内按日期原位重排，组间不移动。
- **F 拖拽**：拖文件夹头=整组移动；拖成员到文件夹=进组；拖到顶层=出组；组内成员拖动=组内换序。
- **G 取消分组**：选中成员 →「取消分组」拆分；组空删除。
- **H 持久化与边界**：连续约束维护；旧数据兼容；空组清理；与现有排序/拖拽/进度显示兼容。
- **I 测试**：视频页/空间页侧边栏实测 成组/重命名/收起展开（默认收起、刷新重置）/成员数/首条摘要/选中勾选指示/拖进拖出/拖标签改位/取消分组/组内自动排序/与现有功能无冲突。

## 5. 决策记录（已与用户确认）

- 按钮名称：**「成组」**。
- 成组规则：**允许重新成组**（选中项并入新组，自动移出原组，原组空则删除）。
- 自动排序与分组：**组内排序、组间不排**；并支持点击组「头」自动全选组内成员再一次整组内排。
- 纳入增强项（四项全选）：**拖进/移出文件夹**、**拖文件夹标签改位置**、**收起时显示成员数**、**取消分组拆分**。
- （用户后续反馈）**移除颜色功能**：分组不再显示/可改颜色标识；组头改为「选中勾选指示 + 名字 + 成员数 + 收起箭头」，并移除组内成员左侧的连接竖线。
- （用户后续反馈）**组头点击可勾选/取消**：点击组头切换选中该组全部成员（已全选再点则取消）。
- （用户后续反馈）**默认收起重置**：每次加载页面把各分组重置为收起，手动展开不跨刷新保持。
- （用户后续反馈）**重命名输入阻止按键冒泡**：避免输入时触发 B 站播放器快捷键（如 `m` 静音）。
- （v1.2.1，后续优化）**组头播放按钮**：文件夹标签新增 ▶，点击播放组内第一个视频、从断点续播。
- （v1.2.2，后续修复）**分P断点续播 bug**：断点保存改分P感知（分P变化即保存，避免新分P time 小于旧分P而跳过）；`jumpToVideo` 以断点分P作为 `?p=`；侧边栏/组头分P显示改用断点分P（如 3/11）。

## 6. 待确认 / 遗留（含已知问题，待修复）

**已知问题（待修复，先记录不动手）：**
- （①）播放完整个视频后，被「自动跳转」到别的视频（视频 B），且该视频 URL 带 `fromPlaylist=1`。**经确认视频 B 不在播放列表中**——插件「播完→跳列表下一个」只会跳到列表内的视频，故不可能跳到 B；这次跳转实为 **B 站自身“自动连播”接管**，而 `fromPlaylist=1` 是 B 站从带该参数的视频 A 跳向 B 时**沿用旧查询参数所致**，并非插件跳转的证明。
  - ⚠️ 补充：**F5 刷新页面**会重置扩展「当前在第几集」的内部记忆（扩展点选集切分P时网址 `p` 常不变，F5 后按旧 `p` 重判），导致之后播完判定出错，间接给 B 站接管创造条件——非直接触发，但与 ①② 同根因（“当前分P”跟踪不可靠）。
  - 🔍 待排查：插件为何未在「A 播完」时正确拦截并跳列表下一个（很可能与 ② 同根因：当前分P号不可靠，插件误以为 A 未播完）；B 站究竟是否在自动跳转时沿用/保留 `fromPlaylist=1` 参数。
- （②）视频全部分P已播完（B 站历史显示 `7/7`），侧边栏仍显示旧分P（如 `3/7`），点击「同步/刷新」后未更新。

**待办（已同意方向，未实现）——断点/连播系统改造清单：**
> 目标：把“事件触发的快照 + 靠扩展数分P + 与 B 站抢跑”改成「**连续记录 + 最小化界面更新 + 以 B 站为准**」。

1. **连续边看边存断点**：改为较高频、规律保存（每 ~10s，或分P/秒数跨阈值时），不再只靠「开播 5s / 关标签 / 切集」几件事。
2. **检测分P切换并记录**：B 站自身自动连播会改变 URL（出现 `?p=2`），因此**监听 URL `p=` 变化**，一旦分P切换就记录一次（补上“B 站驱动切集”时扩展编号跟不上的缺口）。
3. **第几集以 B 站官方为准**：尽量读 B 站在线历史 / URL 分P号作为权威，扩展少自己猜。
4. **最小化界面更新（不整表重建）**：保存时**只原地更新正在播放那一条的文本**（分P+时间），其余不再重建。
5. **仅侧边栏打开时更新显示**：关闭时不做 DOM 更新（省资源）。
6. **数值没变就不触发**：分P 没变、秒数没变就跳过（免写、免更新）。
7. **保持滚动位置**：原地改文本、不清空列表，避免侧边栏跳回顶部。
8. **修正「连播被接管」**：在「播完」时先以可靠分P信息判定是否为最后一集；是则交播放列表/正确路径处理，否则坚决拉住、不让 B 站自动连播接管。

**关于互斥（重点是厘清，非互斥）：**
- **保存与显示是两条独立路径**：断点保存必须在播放标签页**始终执行**（不随侧边栏开关变化）。「仅侧边栏打开才更新」**只约束“显示”的 DOM 更新**，不能拿它去挡保存——否则侧边栏关着就不记断点了，反而更糟。
- **「每 10s」本质是「每 10s 检查一次，变了才写/才更新」**，与「数值没变就不触发」天然配合，不冲突。
- 其余条目相互兼容，可一起做。建议顺序：先「保存侧（1/2/3）」，再「显示侧（4/5/6/7）」，最后「连播判定（8）」。

- 涉及 B 站页面结构/接口假设时，实测后记入 `docs/api-notes.md`。
